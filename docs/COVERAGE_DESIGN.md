# Accountable coverage and contextual interpretation (1.4.0)

## Source and execution contract

The baseline is verified main `6f17fcc8c509428e4ed71c29540896909cbcfd53` (1.3.2). [Baseline reproductions](COVERAGE_BASELINE.md) were committed together with separate development and frozen evaluation fixtures before implementation. No subagents were used.

`src/analysis-pipeline.js` prepares complete cleaned input, source mappings, full fingerprints, deterministic paragraph/sentence chunks and separately labeled neighbor context. A maximum of 4,000 characters and 32 passages keeps individual responses bounded. Oversized passages split without losing text or breaking Unicode surrogate pairs. Paragraph duplicates retain local source references without extra aggregate votes. Prose blockquotes and Mermaid mindmaps survive; frontmatter, fenced code (including long and unclosed fences), headings and non-prose embeds are excluded. Source reads have a 15-second timeout; one unavailable source blocks its date instead of scoring a partial source set.

The saved character setting becomes the per-run source-character budget. Repeated format, completion, transport and review requests and neighboring context consume it. It is never silently increased. JSON/schema/opaque-ID overhead is not source text. Later chunks remain visibly queued and resume. Work is keyed by the complete source and preparation settings, pipeline, provider, model, prompt and chunk identity. Requests remain serialized; five attempts are shared across all recovery modes. One short transient retry follows provider guidance; longer guidance and rate limits go through the existing persistent cooldown scheduler.

`runtime.chunkWork` stores bounded validated interpretations, outcomes, metrics and local mappings, never full raw note text or provider bodies. Each chunk checkpoint is persisted before continuing. Every passage ID must be acknowledged as assessed and all dimensions must resolve before a replacement can commit. A successful HTTP request, nonempty evidence or prefix coverage is insufficient. Interrupted work preserves the prior record; reload revalidates saved anchors and assessments before reuse. Completed work goes through the existing prepared Markdown/JSON transaction and then deletes its staging data. Source, settings, consent, deletion and eligibility events invalidate pending work before further dispatch or commit. New sources invalidate an in-flight scan even when automatic analysis is off.

## Interpretation and persistence contract

Evidence v2 adds exact passage ID/quotation offset, personal/textual basis, direction, explicit/inferred meaning, temporal context, support and ordinal score. Readers still accept historical v1 records. Every dimension distinguishes supported, unsupported, ambiguous, conflict and not_assessed. Only the first three are resolved; supported additionally needs a valid score and evidence. Processing is separate. Neutral writing can complete with all scores null; a minimum-character exclusion stays explicitly not assessed and reports excluded coverage. Historical assessment coverage is unknown.

Exact quotes must occur in their identified passage. Unique exact quotes can repair an offset-counting difference; repeated quotes require an unambiguous correct offset. Context-only quotes never become new evidence. Fabricated anchors, invalid basis, diagnostic labels, bounds failures, absent passage acknowledgments and score/direction contradictions receive bounded reason codes. Textual evidence supports intensity only. English cues can request a review, never veto a grounded contextual provider inference. Negated feeling cues request review rather than mechanically creating the opposite or neutral mood. Review can explicitly abstain. Valid staged dimensions survive a failure elsewhere and resume without repeating the successful work.

Scoring anchors retain the established ordinal scales: mood from strong distress (1) through mixed/neutral (3) to strongly positive (5); energy from depletion (1) to activation (5); connection from isolated/unseen (1) to deeply supported (5); intensity from muted (1) to highly charged (5). Fatigue does not imply distress, activity does not imply connection, and wanting support does not imply receiving it. Confidence is bounded textual support, not psychological certainty.

Aggregation uses every validated interpretation, deduplicating distinct concept/direction/temporal/basis groups and taking their median contributions. Opposing positive and negative poles receive separate support counts and balanced contributions; chunk scores never receive equal votes merely because of artificial boundaries. Explicit temporal observations are retained; file order never defines chronology. Display quotes are selected across dimensions, directions and temporal contexts, capped at 16 after aggregation. Local rules remain conservative English-only. Historical comparisons require matching evidence versions, analyzer/provider/model/source scope and date basis, and remain local.

## Display, upgrade and repair

Each axis has its own finite-score population. Charts retain dates with other supported dimensions; missing values are never plotted as zero or neutral. Following the user's chart feedback, available readings stay connected: regular segments join adjacent supported dates, and lighter dashed connectors explicitly identify unscored intervals. Tooltips and the chart caption explain those intervals. Toggles hide both regular and gap connectors and preserve keyboard focus.

Dashboard status distinguishes queued, processing, awaiting retry, partially assessed, stale, current, assessed without support and minimum-policy exclusions. Null axes show concise assessment reasons. The repair preview reads locally and estimates chunks and primary-to-maximum request counts. A batch starts unchecked and requires explicit selection. Display-only repairs call no provider. Missing/unreadable/below-minimum sources are blocked with reasons. Legacy remote results are conservatively stale even when an old preparation hash cannot be compared; upgrading never automatically sends unknown historical coverage. Existing scores, identities, edited generated notes, paths and provider consent remain readable.

## Acceptance evidence and costs

- [Frozen local comparison](COVERAGE_LOCAL_EVALUATION.json): local mood 4/9 and connection 2/8; no unsupported scores, unchanged from 1.3.2. Local rules do not claim parity with contextual remote inference.
- [Final repeated Groq 120b comparison](COVERAGE_LIVE_EVALUATION.json): all repetitions, required ranges, separate mood/connection recall, unsupported opportunities, unresolved cases, request/token usage and latency. The unchanged 1.3.2 comparator is reused from the initial three-repeat run and explicitly identified in the report.
- [Initial live comparison](COVERAGE_LIVE_INITIAL.json) and [resolved-contract comparison](COVERAGE_LIVE_CONTRACT.json) preserve earlier completed trials instead of selecting only a favorable run. Earlier first-pass and recovery trials are also retained. Intermediate development contracts that confused unsupported/neutral interpretation with unprocessed source were rejected and corrected before acceptance. Completion recovery/format fallback share the same budget even during review. Pending review target lists are recomputed after merging preserved valid dimensions, and quotation-bounds feedback asks for short supporting clauses. Diagnostic labels on otherwise grounded textual intensity are removed with reduced support rather than persisted or replaced with invented clinical claims.
- [Local performance and metadata](COVERAGE_PERFORMANCE.json): small entries, long dates, dates beyond the old cutoff and 1,000-file dates. The current path pays for complete coverage and local mappings; the old 60,000-character prefix is not equivalent work. Pending results are removed after final commit. There is no global raw-text cache. CPU yields between local chunks and source batches.

The frozen corpus contains broad supported ranges, indirect relational expression, negation, attribution, sarcasm, mixed/temporal states, short entries, multilingual writing and neutral text. Long source accounting, mixed/polarity retention, changed chunk boundaries, duplication, reordering and neutral padding have dedicated regression tests; native long-date verification is recorded separately without private text. These engineering checks cannot prove complete psychological recall, universal multilingual coverage or clinical accuracy. Obsidian provides no cross-file fsync transaction guarantee; the existing prepared-write replay protocol remains the recovery mechanism. Requests already dispatched cannot be recalled after opt-out.

Full functional/syntax/build, responsive layout, emotional benchmark, release privacy and diff checks are required before publication. New coverage reproductions and contract/recovery tests run in the normal suite and CI. Native and release evidence is finalized in PROJECT_STATE.md and PROGRESS.md.

Final exact-build live results (three repeats, 18 frozen cases): mood 27/27, connection 24/24, all 57/57 required score constraints. Unsupported inferences decrease from 5/66 to 0/66; final unresolved cases: 0. Requests: 70 → 59. Median execution latency: 3.76s → 5.61s. Input/output tokens: 174,422/75,080 → 218,848/109,212. The richer contract increases token cost and latency despite fewer requests; this is an accepted measured tradeoff for explicit coverage and validation. Earlier trials include an initial unresolved mixed-emotion case; pending/recovery is reported rather than silently scored. Completed wrong scores are never retried for a favorable outcome.
